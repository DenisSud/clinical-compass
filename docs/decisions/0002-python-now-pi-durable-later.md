# ADR-0002: Сейчас Python и Ollama, pi-durable позже

Дата: 2026-10-20
Статус: принято

## Контекст

Целевая архитектура — один агент с устойчивым состоянием на `pi-durable`,
который ведёт диалог с врачом и переживает перезапуск. Это проверенная
технология (используется в mason). Но `pi-durable` — TypeScript, а клиническое
ядро — Python, и до сдачи 10 дней при двух технических участниках.

## Решение

Сейчас — `ollama-python` и обычные вызовы внутри `packages/compass_ai`. Никакого
второго рантайма.

Граница зафиксирована интерфейсом `compass_ai.assistant.Assistant`. Клиническое
приложение не импортирует `Ollama` напрямую и не знает, откуда пришёл ответ.
Когда pi-durable понадобится, появится вторая реализация Protocol поверх
HTTP-сервиса — `apps/api` не изменится.

## Последствия

Проще: один язык, один venv, один деплой, ноль интеграционной отладки.

Дороже: пока нет устойчивости к падению процесса и проактивных запусков.
Поэтому доставка алертов проектируется как запись в БД + отдельный воркер, а не
как «модель не забудет» — так требование «алерт не теряется» выполняется без
pi-durable.

Нельзя: строить алертинг на том, что процесс допишет уведомление до конца.
