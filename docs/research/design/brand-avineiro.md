## 0. Как проверять замеры

Каждое значение в этом файле получено инструментом, а не на глаз. Кто проверяет — повторит
одной командой.

| Что измеряли | Чем | Точность |
|---|---|---|
| Векторные заливки и обводки (текст, плашки, линейки, фоны) | `pdftocairo -svg -f N -l N` → разбор `fill="rgb(r%, g%, b%)"` и `stroke=` в SVG | точный цвет PDF; пересчёт % → hex даёт ±0 |
| Кегль, гарнитура, цвет строки | `pdftohtml -xml` (`<fontspec size family color>`) + `pdffonts` (встроенность) | кегль pdftohtml отдаёт в масштабе 1.5×; делили на 1.5 |
| Позиции текста и фигур | `pdftotext -bbox`, координаты `<use x y>` в SVG (pt, начало — левый верхний угол) | ±0.5 pt |
| Растровые ассеты (логотип, упаковка, таблица, список) | `pdfimages -list` + `pdftoppm -r 200` → разбор PPM P6 вручную, модальный цвет области | ±2–4 на канал (JPEG и ресемплинг) |

Оговорка о точности: `pdftohtml` усекает младший разряд (`#9474b5` вместо `#9574B5`).
Ниже везде значения из SVG — они точные.

Команды целиком:

```bash
pdftoppm -r 200 brand.pdf pg            # растры для замеров
pdftocairo -svg -f 10 -l 10 brand.pdf s10.svg   # векторные цвета
pdftohtml -xml brand.pdf all.xml        # кегли и цвета строк
pdfimages -list brand.pdf               # какие картинки встроены
pdffonts brand.pdf                      # гарнитуры и встроенность
```

## 4. Форма

**Радиусы.** В векторных объектах PDF нет ни одной дуги: ни `rx` у прямоугольников, ни
команды `A`/`a` в путях. Все поверхности — с радиусом 0. Единственная скруглённая форма —
«пилюля» на слайде 6 (плашки списка преимуществ, растр): полное скругление, r = h/2.
На упаковке препарата плашка дозировки «20 мг» скруглена примерно на 10 % высоты.

**Тени.** Ни одного `feGaussianBlur` / `feDropShadow` во всех 8 проверенных SVG. Тень есть
только внутри 3D-рендера упаковки (растр). Иерархия в источнике строится **не тенью**,
а двумя приёмами: (1) фон-полоса (`#EAF6F6`, `#FAF6FF`, тона строк таблицы) и (2) линейка
1–4.5 pt (`#E8D5C5`, `#BBC8D1`, `#EDAF3F`, `#B499BE`). Это и надо переносить: у нас
`--shadow-none: none`.

**Сетка.** Единой сетки нет, поля разные: левый край заголовка слайда 3 — 20.9 pt,
полосы слайда 9 — 29.3 pt, заголовка слайда 6 — 35.3 pt. Внутри полосы слайда 9 четыре
колонки стоят по x = 41.6 / 269.7 / 415.5 / 599.1, то есть зазоры 73 / 67 / 58 pt —
колонки выставлены на глаз, а не по модулю. **Колонок мы не наследуем**; берём только
принцип «полоса на всю ширину с равными блоками».

**Плотность.** Таблица слайдов 3–4: шаг строки 10.0–10.25 pt при кегле 8.3 pt, то есть
1.2 кегля; 32 строки умещаются в 340 pt высоты. Разделители — белые линии 1 px, не серые.
Это самый плотный образец в файле; для веба он недостижим и не нужен — в токенах
`--row-dense: 28px` (наш шаг, не из источника).

**Композиционные приёмы, которые видно на слайдах** (это и есть переносимая «форма»):

1. *Обложка*: полноэкранная фотография + диагональная полупрозрачная вуаль бренд-цвета
   (78.8 %), поверх — заголовок, белая линейка 3 pt длиной 199 pt, логотип.
2. *Две колонки + центральный объект* (слайд 2): три площадки слева, три справа, между
   ними круг с картой мира и линии-связки.
3. *Таблица с цветными метками групп* (слайды 3–4): вертикальная цветная полоса группы
   + чередование тонов строк + полосы-«гант» по фазам.
4. *Воронка* (слайд 5): трапеция бренд-цвета с числами, над ней ряд иконок с подписями.
5. *Тизер-список* (слайд 6): круглый значок с галочкой + вытянутая «пилюля» под текст.
6. *Полоса-вывод* (слайд 9): мятная плашка на всю ширину, внутри 4 колонки «заголовок +
   подпись», между колонками двойные стрелки. Это ближайшее к интерфейсу, что есть в файле.

логотипа, значит при высоте 64 px её кегль ≈7 px — предел читаемости. Меньше 64 px по
высоте логотип не ставить.

**Чего нет:** нет логотипа в один цвет, нет версии без подписи «ГК ХимРар», нет
горизонтальной/квадратной компоновки. Всё это придётся запрашивать у правообладателя,
если логотип вообще будет использоваться (см. §9).

### 5.6. Чего в файле нет

Скриншотов продукта, мокапов экранов, иконок интерфейса, компонентов (кнопок, полей,
таблиц-виджетов), курсоров, иллюстраций людей в UI. **Ни одного элемента их собственного
интерфейса в презентации нет** — это презентация компании и препарата, а не продукта.

Ближайшее к «интерфейсу» — полоса слайда 9 (4 колонки «заголовок + подпись» с двойными
стрелками между ними). Она концептуальная: показывает не экран, а логику
«дополнительная ценность → динамика состояния → интерфейс обратной связи → свои результаты».
Как референс раскладки она даёт ровно одно: равные блоки в один ряд, заголовок 14 pt bold
цветом, подпись 13 pt серым, связи между блоками — стрелками, а не отступами.

## 6. Тон подписей

Цитаты дословные, из `pdftotext -layout`.

| Слайд | Формулировка | Что видно |

| 6 | «15 лет исследований и 3 полученных патента» | число первым, единица рядом |
| 2 | «Исследования, разработка и продвижение оригинальных ЛП для лечения заболеваний ЦНС» | существительные-процессы, никаких глаголов в 1-м лице |
| 10 | «Спасибо за внимание!» | единственный восклицательный знак в файле |

Правила, которые из этого следуют (наша интерпретация, не цитата):

1. **Заголовок — существительное, не глагол.** «Обратная связь врача и пациента между
   визитами», а не «Свяжите врача с пациентом».
2. **Оценок нет, факты есть.** «Врач может узнать об этом только на следующем визите» —
   утверждение о процессе, а не «это плохо». Совпадает с §2.2: никаких «стало лучше».
3. **Число первым и жирным**, единица измерения рядом: «20 мг», «30 таблеток»,
   «5 клинических кандидатов», «более 1800 человек».
4. **Обращение к пользователю отсутствует вовсе** — ни «вы», ни «ваш». Источник говорит
   о третьих лицах («пациент», «врач»). Для нас это удобно: наши экраны тоже говорят
   «пациент», «ведущий врач» (GLOSSARY.md).
5. **Формула «между визитами»** — их способ назвать промежуток, в котором живёт наш продукт.
   Годится в подзаголовках вместо «monitoring»/«в перерыве».

**Слова, которые стоит взять из их лексикона:** «визит», «приём» (в смысле «пациент
прекращает приём»), «назначения», «шкалы», «самочувствие», «динамика состояния».
Последние два — с оговоркой:

- «самочувствие» у них означает наш «дневник самочувствия» (GLOSSARY.md) — совпадает;
- «динамика состояния» — понятие **врачебное**. На экране пациента эта фраза нарушает §2.2,
  поэтому берём её только для кабинета врача.

**Слова, которые брать не надо:** «интерфейс обратной связи» (у нас «сигнал» и «разбор
сигнала»), «препарат как инструмент врача» (у нас нет препарата в продукте).

## 7. Черновик `tokens.css`

Вставляется в `web/src/styles/tokens.css` (каталога `web/src/styles/` пока нет — сейчас всё
в одном `web/src/styles.css`; файл создаётся этим черновиком). Синтаксис проверен
`lightningcss` (тот же парсер, что у Vite): 88 объявлений, ошибок нет.

Порядок объявления — не стилистика, а требование #4 и DESIGN.md §2.3: сначала резервируются
семантические слоты, потом подставляется бренд. Значения слотов никогда не берутся из
брендовой группы.

 *   2. бренд — палитра, снятая с презентации;
 *   3. производные — текст, поверхности, границы, шкалы, типографика.
 *

 * из группы 2. Бренд подставляется в слоты, а не наоборот; если брендовый
 * цвет совпал по назначению с семантическим — меняется бренд, не семантика.

     визитами»), затемнён на один шаг до #9E3B12, чтобы текст на заливке

## 10. Что осталось непроверенным

1. **Письменное разрешение на логотип и на формулировку «фирменные цвета»** — не получено.
   Пока его нет, §9 действует в полном объёме.
2. **Регистрация товарного знака «Авинейро».** Проверить не удалось: открытого реестра
   Роспатента, пригодного для запроса без ключа, нет; в выдаче — только данные ЕГРЮЛ
   (ООО «Авинейро», ИНН 5047227729, Химки) и сайт-заглушка `avineuro.ru`. То, что знак
   используется с «®»-логикой (в презентации — только «АВИАНДР®»), не доказывает регистрацию
   словесного знака «Авинейро». Для §9 это не меняет вывод: разрешение нужно в любом случае.
3. **Точное начертание Lato для чисел на слайде 5.** В PDF вложены только `Lato Black` и два
   подмножества `Lato Light`, а числа «100 000 000» выглядят полужирными. Либо это
   синтезированное утолщение PowerPoint, либо подмножество названо неточно — по файлу
   неразрешимо. На токены не влияет (числа у нас набраны тем же Lato Bold).
4. **Растровые цвета** (`#0051F8` логотипа, `#74C092` плашки на упаковке, цвета таблицы,
   `#207088` знака группы) — точность ±2–4 на канал; для ревью это допустимо, для
   пипетки «в пиксель» — нет.
5. **Тёмная тема.** В презентации её нет; выдумывать палитру мы не стали — токены только
   для светлой темы. Если тёмная понадобится, это отдельное решение с новыми замерами
   контраста.
6. **`#C04F15` как текст** проходит AA с запасом 0.01 (4.51 против 4.50). Формально да,
   практически — на границе; в вёрстке использовать как заливку под белый текст (4.80),
   а текстом — только начиная с 16 px.
7. **Наш текущий макет v5 не в этой палитре.** В `Clinical_Compass_2026-10-23_v5.pptx`
   используются зелёные `#153D38`, `#17766C`, `#5D746D`, фон `#F5F7F3` и Arial; тема
   Office по умолчанию — `#4472C4` / `#ED7D31`. То есть демо и слайды после перекраски
   разойдутся, пока pptx не приведут к этим токенам. Это работа по #4, здесь только
   зафиксировано расхождение.
8. **Скриншотов их продукта не существует в файле** — если они есть у компании, это самый
   ценный материал для раскладки, и его надо запрашивать отдельно (у И. Иващенко).
