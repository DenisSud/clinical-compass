# Что это

Django-приложение `clinical_compass_app`, запуск через `START_DEMO.cmd`. Роли: врач, пациент,
оператор. Деморежим (`DEMO_MODE`), синтетические данные. Пять источников в
`knowledge_examples/team_sources`: КР «Депрессивный эпизод, РДР» (124 фрагмента), а также
бланки PHQ-9, BDI, HADS.

# Сущности (models.py)

| Сущность | Смысл | Ключевые поля |
|---|---|---|
| `User` | роль `doctor` / `patient` / `operator` | `role`, `display_name` |
| `CareRelationship` | привязка пациента к ведущему врачу | уникальность «один активный врач на пациента», запрет «врач = пациент», `is_active`, `ended_at` |
| `Invitation` | код привязки | `token_hash` (sha256), `expires_at` (48 ч), `used_at`, `revoked_at` |
| `SelfReport` | дневник самочувствия | `wellbeing` 1–10, `note` ≤ 2000, `reported_for`, `submission_key` (идемпотентность) |
| `ReportReview` | отметка врача «посмотрел» | `reviewed_at` |
| `SupportRequest` | обращение к врачу | категории `question` / `organization` / `report`, `body`, `response`, `answered_by` |
| `Assessment` | прохождение шкалы | `instrument_code`, `instrument_version`, `definition_sha256`, `definition` (снимок формы), `answers` (JSON), `total`, `completed_count`, `period_start/end` |
| `AssessmentReview` | разбор опросника врачом | `reviewed_at` |
| `AssessmentAttention` | «требует внимания» | `reason` = `q9_positive` / `q9_missing`, `acknowledged_by/at` |
| `SourceDocument` | версия источника | `kind` = guideline/label/scale/synthetic, `sha256`, `applicability`, `usage_rights`, `review_status` = unverified |
| `KnowledgeSnapshot` | неизменяемый текст источника | `text`, `text_sha256`, `bundle_sha256` |
| `KnowledgePassage` | фрагмент с локатором | `key`, `locator`, `start`, `end` (смещения в тексте, ≤ 12000 знаков) |
| `AuditEvent` | журнал действий | `actor`, `action`, `entity_id`, `details` |

# Логика, которая в прототипе есть

1. **Привязка.** Врач выпускает токен на 48 ч, хранится только `sha256`; пациент вводит токен
   один раз; повторная привязка невозможна, пока активна текущая; каждое действие пишется в аудит.
2. **Идемпотентность.** У `SelfReport`, `SupportRequest`, `Assessment` есть `submission_key`;
   повтор с теми же данными возвращает существующую запись, повтор с другими данными — ошибка.
3. **PHQ-9.** Версия формы фиксируется хешем; ответы принимаются только полным набором ключей,
   пропуск — явное `null`; **сумма считается только при девяти ответах из девяти**, иначе `total = null`;
   девятый пункт (`q9`) отдельно поднимает `AssessmentAttention` с причиной `q9_positive`
   или `q9_missing`; обязателен ответ о повседневных затруднениях, если хоть один балл > 0.
4. **Динамика.** `timeline()` считает дельту только между соседними полными результатами одной
   версии формы при уникальных метках времени; неполный результат разрывает сравнение.
5. **Знания.** Импорт пакета JSON: версия источника неизменяема (перезапись запрещена),
   текст хранится снимком и хешем, фрагменты адресуются смещениями, все источники помечены
   `unverified`. `search_staging()` — буквальный поиск подстроки для врача, «никогда не контекст
   для ассистента».
6. **Изоляция.** Врач видит пациента только через активную `CareRelationship`, проверка идёт
   в каждом запросе (`_patient_relation`, `doctor_assessment`), объекты блокируются `select_for_update`.

# Логика, которой в прототипе нет

- **Нет рекомендаций по терапии.** Ни одной карточки препарата, ни правила «первая линия»,
  ни дозирования: корпус только читается и ищется.
- **Нет маршрутизации к психиатру.** Кейс требует «обязательно / желательно», в коде этого нет.
- **Нет правил сигналов.** Есть только `AssessmentAttention` по девятому пункту — единственное
  правило в системе.
- **Нет плана лечения** как сущности: ни назначений, ни подтверждения врачом.
- **Нет приёма/консультации** как события: нет ни первой консультации, ни повторного приёма,
  ни направления от терапевта к психотерапевту.
- **Нет опросника при входе** (персональный бланк из `08-intake-questionnaire.md`).
- **Нет шкал, кроме PHQ-9 в коде** — BDI и HADS лежат только как текстовые источники.

# Что из этого следует для «логики решений»

Прототип — это **сбор и хранение** с одной охранной сигнализацией (девятый пункт PHQ-9).
Решений он не принимает и не предлагает. Значит, логика «вход → выход», которую предстоит
определить, в коде ещё не существует: её нужно спроектировать, а не дочитать.
