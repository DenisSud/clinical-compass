# TypeScript на всём стеке: Fastify + Drizzle + SQLite + React/Vite

Приложение — веб-сервис с двумя ролями, а модель вынесена за границу OpenAI-совместимого
HTTP API, поэтому второй язык ничего не даёт. Один язык на всём стеке: Fastify 5 отдаёт и
API, и собранный статический фронтенд из одного процесса; Drizzle описывает схему и
миграции; SQLite в режиме WAL хранит данные; React 19 + Vite — SPA.

**Status**: accepted

## Рассмотренные варианты

- **FastAPI / Django** — второй язык и второй слой валидации ради экосистемы, которая нам
  не нужна: модель вызывается по HTTP, а вся работа приложения — CRUD, правила и SSE.
- **Next.js** — за аутентификацией нечего отдавать по SSR; лишний сервер и лишняя
  сложность деплоя.
- **Go / Rust** — производительность выше, время написания в 2–3 раза больше, а узкое
  место — задержка модели, а не фреймворк.
- **Postgres с первого дня** — честнее по метрике масштабируемости, но требует сервиса и
  инфраструктурных миграций. Переезд с SQLite — замена драйвера Drizzle, пока приложение
  живёт в одном процессе.

## Последствия

- Один процесс, один порт, один origin: cookie-сессии работают без CORS, деплой — один
  контейнер.
- SQLite ограничивает одним пишущим узлом. Это осознанно: пока приложение — один процесс,
  второй экземпляр невозможен. Точка переезда — когда понадобится горизонтальное
  масштабирование.
- Быстродействие (метрики 1 и 6) решают потоковая передача ответов модели, отсутствие N+1
  и индексы, а не фреймворк. Записано здесь, чтобы никто не «оптимизировал» стек вместо
  запросов.
