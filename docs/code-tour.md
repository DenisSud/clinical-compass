# Как читать этот код

Порядок чтения и что искать в каждом файле. Всего ~2200 строк: за один вечер
можно прочитать целиком, но не в том порядке, в котором файлы лежат на диске.

## Правило зависимостей

```
compass/instruments  ─┐   только stdlib
compass/knowledge    ─┴─→  compass/ai  (+ httpx, subprocess)
                              ↓
                          apps/api  (когда появится)
```

`instruments` и `knowledge` не импортируют ничего вне стандартной библиотеки.
Поэтому подсчёт шкалы проверяется тестом без модели, без БД и без сети. Если
когда-нибудь понадобится прогнать шкалу в скрипте на пустой машине — она
заработает.

## Читать в этом порядке

### 1. `compass/__init__.py` — 40 строк, карта

Публичная поверхность: `load`, `load_strict`, `score`, `load_dir`,
`LocalAssistant`, `ModelRoles`. Если вы забудете, что здесь есть, — начните
отсюда.

### 2. `compass/instruments/definition.py` — 298 строк, самый большой файл

JSON-определение шкалы → замороженные dataclass'ы. Строгая валидация: лишний
ключ, неизвестный пункт, не монотонные границы — всё падает с внятным сообщением.

Три вещи, которые здесь важны:

- **`canonical_json` и `sha256`.** Определение шкалы сериализуется
  канонически, хэш попадает в каждый сохранённый результат. Через полгода можно
  доказать, какую именно версию шкалы видел пациент.
- **Порядок вариантов сохраняется.** На HADS часть пунктов идёт от «очень часто» к
  «никогда», то есть баллы убывают. Сортировать варианты по баллам — значит
  изменить валидированный бланк. В коде на это есть комментарий.
- **`_ALLOWED_TOP`.** Белый список ключей верхнего уровня. Опечатка в JSON
  (`"saftey"`) не будет молча проигнорирована.

Смысл всего файла — **шкала это данные, не код**. Метрика 10 кейса проверяется
так: положили JSON в `definitions/` — шкала появилась.

### 3. `compass/instruments/scoring.py` — 128 строк, две клинические ошибки

Чистая функция `score(instrument, answers) -> Score`. Здесь зафиксированы два
правила, которые легко нарушить и которые дорого стоят:

- **`None` — это «не отвечено», а не ноль.** Если пропущен хоть один пункт
  подшкалы, её сумма `None`, а не заниженное число. Частично заполненный PHQ-9 не
  должен выглядеть как лёгкая депрессия.
- **Сигналы безопасности считаются даже при неполной форме.** Пункт 9 PHQ-9 выше
  нуля — это клинически значимо само по себе, независимо от того, заполнены ли
  остальные восемь.

`Score` неизменяем и несёт `definition_sha256`, `completed`, `required`,
`findings`. Поле `complete` — свойство, не хранится.

### 4. `compass/instruments/registry.py` — 91 строка

Загрузка всех `*.json` из `definitions/`. Ключевое: `load()` **собирает** ошибки
в `LoadReport.errors`, `load_strict()` их **бросает**. Два режима нужны, чтобы
кривой файл в продакшене не убивал приложение, а в тесте — убивал.

### 5. `compass/knowledge/passage.py` — 30 строк

`Passage`: ключ, источник, локатор, текст, `start`, `end`. Смещения — это и есть
вся идея. Цитата рендерится как `bundle.text[start:end]`, то есть буквальная
цитата, а не пересказ. «Научная обоснованность» из критериев кейса превращается
из заявления в проверку.

Этот файл лежит в `knowledge`, а не в `ai`, потому что фрагмент — факт о
документе, а не о поиске.

### 6. `compass/knowledge/bundle.py` — 154 строки

Загрузчик корпуса в формате Антона (не меняли, чтобы не переделывать 124
фрагмента). Проверяет `text_sha256`, границы смещений, непустоту фрагментов,
уникальность ключей.

### 7. `compass/ai/retrieval.py` — 150 строк, гибридный поиск

BM25 (лексика) + косинус по эмбеддингам (смысл). Оба нужны, потому что:

- клинические запросы полны редких точных токенов — МКБ-коды, «Чайлд-Пью»,
  «СКФ» — где лексика выигрывает;
- и полны перефразов — «плохо спит» против «инсомния» — где выигрывает вектор.

Без numpy и без векторной БД. 132 фрагмента помещаются в память, цикл занимает
микросекунды. Токенизация — просто `\w+` в нижнем регистре, **без стемминга**:
русская морфология это отдельный проект, а BM25 по стеммам был бы враньём о том,
как он настроен.

`Index.embed()` опционален. Нет эмбеддингов — поиск работает лексически, не падает.

### 8. `compass/ai/ollama.py` — 230 строк, единственное место, где есть модель

**Два транспорта, и это не ошибка:**

| Транспорт | Для чего | Почему |
|---|---|---|
| HTTP `/api/chat`, `/api/embed` | рассуждение, эмбеддинги | обычный путь |
| CLI `ollama run d1 --ask` | решения (`d1`) | у `d1` `capabilities: ["decision"]`, и в Ollama 0.40.4 **нет HTTP-эндпоинта**: и `/api/chat`, и `/api/generate` отвечают «does not support chat» |

Мост через `subprocess` изолирован в `decide()` и помечен как временный. В день,
когда появится эндпоинт, эта функция удаляется целиком, и больше ничего не
меняется.

Ещё здесь:

- `resolve()` — Ollama отдаёт имена с тегом (`nomic-embed-text-v2-moe:latest`),
  поэтому голое имя надо сопоставлять с неявным тегом.
- Пустой ответ модели — это `OllamaError`, а не пустая строка. `qwen3.5:4b` без
  `think: false` уходит в размышления и возвращает пустоту; это классический
  молчаливый отказ, и он должен быть громким.
- `Decision.confidence` в docstring прямо назван тем, что он есть: проценты
  модели, **не** калиброванная вероятность.

### 9. `compass/ai/triage.py` — 202 строки, главный инвариант

> **Модель может повысить внимание. Понизить — никогда.**

Здесь это записано в коде, а не в презентации.

- `from_instrument(score)` → находки шкал, `authoritative=True`.
- `screen_text(ollama, text)` → 5 бинарных скринов (`SCREENS`) через `d1`,
  `authoritative=False`, уверенность приложена.
- `merge(*groups)` → сортировка `(not authoritative, -rank, signal)`: сначала
  авторитетные, внутри — по срочности.

Почему так: обязательное условие кейса — система не действует клинически сама.
Но и без этого `d1` — классификатор на 2.7B. Он ошибается на отрицании,
сарказме и разговорном русском. Его 93% не должны перевешивать «пункт 9 выше
нуля».

`screen_text` не бросает исключений никогда: упавшая модель не должна мешать
сохранить сообщение пациента. Отказ виден как `screen_unavailable` в очереди
разбора — пробел виден, а не молчит.

### 10. `compass/ai/drafting.py` — 147 строк, цитатный шлюз

`draft()` возвращает `Draft`, где каждое утверждение несёт ключи фрагментов, на
которых стоит. Шлюз:

- сослался на фрагмент, которого не давали → `DraftRejected` на весь черновик;
- утверждение без единой ссылки → `DraftRejected`;
- нечего цитировать → черновика нет вообще, и **модель не вызывается**.

`Draft.requires_doctor_confirmation` всегда `True` и не параметризуется.

Почему отвергается весь черновик, а не одно утверждение: правдоподобная
непрослеживаемая рекомендация хуже отсутствия рекомендации.

### 11. `compass/ai/assistant.py` — 139 строк, шов

`Assistant` — Protocol из семи методов. `LocalAssistant` — реализация на Ollama,
которая деградирует в `None` вместо исключения.

Это то место, где появится pi-durable. Клиническое приложение зависит от
Protocol, а не от `Ollama`. Захотим одного агента с состоянием и проактивными
запусками — пишем вторую реализацию, `apps/api` не меняется.

### 12. `compass/ai/models.py` — 51 строка

Три роли, три модели, все локально. `TARGET_REASONING_MODEL = "bonsai-2:27b"`
задокументирован, но **не** выставлен по умолчанию: отсутствующая модель не
должна валить демо.

## Сквозной сценарий

Пациент заполнил PHQ-9 и написал врачу «мне хуже, таблетки не пью».

```python
from compass import LocalAssistant, load_dir, load_strict, score

registry = load_strict()
result = score(registry.get("PHQ9-RU"), answers)        # None = не отвечено

assistant = LocalAssistant()
assistant.load_corpus(load_dir()[0])                    # 132 фрагмента

candidates = assistant.triage(score=result, text="мне хуже, таблетки не пью")
```

Что произошло внутри:

1. `score()` посчитал сумму по подшкалам или `None`, если чего-то не хватает, и
   собрал `findings` из правил безопасности (пункт 9, пункт 9 без ответа).
2. `from_instrument()` превратил находки в `Candidate(origin="instrument",
   authoritative=True)`, добавил `severe_score`, если сумма в тяжёлой полосе.
3. `screen_text()` прогнал пять бинарных вопросов через `d1` по CLI. На «таблетки
   не пью» сработает `stopped_medication`, на «мне хуже» — `worsening`. Оба
   `authoritative=False`.
4. `merge()` поставил находки шкалы выше, модельные — ниже, с уверенностью.

Врач видит очередь, где визуально различаются «правило шкалы» и «подозрение
модели». Это различие — часть интерфейса, а не деталь реализации.

Дальше, если врач спросит «что делать»:

```python
hits = assistant.retrieve("серотониновый синдром при сочетании с СИОЗС", limit=5)
draft = assistant.draft(question="...", hits=hits, context="...")
```

Каждое утверждение черновика несёт ключи `hits`. Если модель сослалась на
что-то, чего в `hits` нет, — `draft()` вернёт `None` (исключение проглочено
`LocalAssistant`), и врач увидит «нет обоснованного ответа» вместо красивой
выдумки.

## Где искать при отладке

| Симптом | Где смотреть |
|---|---|
| Модель молчит, ответ пустой | `models.thinking`; `qwen3.5:4b` нужен `think: false` |
| «does not support chat» | это `d1` — он только через CLI, см. `ollama.decide()` |
| `model(s) not installed` | `ollama.resolve()`, теги `:latest` |
| Шкала даёт `None` вместо суммы | ожидаемо: есть неотвеченный пункт, см. `scoring._score_subscale` |
| Черновик всегда `None` | скорее всего `DraftRejected` — модель сослалась на несуществующий ключ |
| Поиск ничего не находит | проверьте `make corpus`; BM25 без стемминга, ищите по корню слова |

## Чего здесь намеренно нет

- **Свободного чата с моделью.** Каждый вызов — конкретный вопрос с конкретным
  ответом. Беседа без границ не даёт гарантий, которые нужны в медицине.
- **Векторной БД.** 132 фрагмента не требуют инфраструктуры.
- **Стемминга.** См. выше — честность о настройке важнее процента попаданий.
- **`apps/api`.** Решение не принято: см. `apps/README.md`.
- **C-SSRS с ветвлением.** Текст шкалы в корпусе есть, движок ветвления — нет.
  Нынешняя схема определения выражает только плоский сумматор.
