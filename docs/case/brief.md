# Кейс: Цифровой ассистент врача при тревожно-депрессивной симптоматике

Источник: `docs/sources/case-brief.pdf`
Чемпионат: «Клинический компас», команда 6-И. Трекер: Наталья.
Партнёр / владелец кейса: ГК ХимРар, ООО «Авинейро». Препарат-якорь: **Авиандр**.

## Формулировка задачи

> Создать инструмент поддержки принятия врачебных решений для ведения пациентов
> с тревожно-депрессивной симптоматикой.

Акцент на **поддержке принятия решений** (CDSS), а не на диагностике и не на
самостоятельном назначении терапии.

## 8 функций инструмента (каждая оценивается отдельно)

| # | Функция | Что это значит для нас |
|---|---|---|
| 1 | Стандартизированные методы оценки состояния | Библиотека валидированных шкал, версионирование, автоматический подсчёт |
| 2 | Рекомендации / справка по вариантам терапии | RAG по клинрекомендациям Минздрава + инструкции препаратов, **со ссылкой на фрагмент источника** |
| 3 | Учёт и оценка индивидуальных рисков и нежелательных явлений | Реестр НЯ, противопоказания, лекарственные взаимодействия |
| 4 | Мониторинг динамики | Временные ряды по шкалам, тренд, сравнение с предыдущим визитом |
| 5 | Интерфейс пациента для самоотчёта и самостоятельного трекинга | Дневник, шкалы, график динамики |
| 6 | Каналы коммуникации для сопровождения лечебного процесса | Асинхронные обращения пациент→врач и ответы |
| 7 | Оценка приверженности лечению и рекомендациям | Приём препарата, пропуски, заполнение дневника |
| 8 | Выявление ситуаций, требующих направления к психиатру + маршрутизация | Правила эскалации, приоритеты «обязательно» / «желательно» |

Функция 8 — сильнейшая подсказка о целевой роли врача: инструмент для врача
**не-психиатра**, который должен понять, когда передавать пациента психиатру.

## Обязательные условия (жёсткие гейты)

1. **Минимум две роли** — «Врач» и «Пациент», раздельные функции и права доступа.
2. **Связь «врач-пациент»**. Данные пациента привязаны к ведущему врачу; введённое
   пациентом попадает в его карточку у врача **без участия третьих лиц**.
3. **Решение не выполняет клинических действий самостоятельно.** Назначение, изменение
   и отмена терапии, направление к психиатру, изменение плана лечения — только после
   подтверждения врачом.
4. **Клинические сценарии с назначением «Авиандра».** Каждый сценарий включает профиль
   пациента, рекомендации по лечению, маршрутизацию.
5. **Механизм алертинга.** Система сама определяет критическое состояние по признакам
   (перечень определяет команда), **экстренно оповещает врача**, выполняет ряд действий
   (определяет команда).
6. **Визуальная иерархия сигналов.** Направление к психиатру и предупреждения о
   безопасности терапии визуально выделены; «обязательно» и «желательно» различимы.
7. **Только препараты, зарегистрированные в РФ**, в пределах зарегистрированных
   показаний, противопоказаний, режимов дозирования. Off-label — только решение врача.
8. **Источники.** Клинрекомендации — действующие, одобренные Минздравом России.
   Международные — допустимы как дополнение с явным указанием источника. Препараты — по
   действующей инструкции из ГРЛС. Шкалы — валидированные, с валидированной
   русскоязычной версией; указать источник валидации и соблюсти условия использования
   (авторские права, лицензия).
9. **Соответствие законодательству РФ.**
10. **Конфиденциальность.**

## Чего в кейсе нет

- Бюджета, стека, требований к хостингу.
- Явного требования LLM. «ИИ» в названии кейса — это про ассистента, а не про чат.
- Требования к мобильному приложению.
- Разрешённого списка шкал.
